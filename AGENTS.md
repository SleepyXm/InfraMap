# Code style

- Prefer readable structure over forced density.
- Keep an expression on one line when splitting it adds no useful meaning.
- Unwrap code when the separation exposes distinct steps, decisions, or responsibilities.
- Do not compress callbacks, error handling, or unrelated operations onto one line.
- Use blank lines to separate concepts, not to add decorative space.
